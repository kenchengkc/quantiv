# Repository state policy

## Purpose

Quantiv separates source code from mutable production state. Git is the source of truth for code, schemas, configuration, small deterministic fixtures, and human-reviewed documentation. Object storage and generated release artifacts are the source of truth for mutable market data, model bundles, publication snapshots, and operational evidence.

## Keep in Git

- Application and pipeline source code.
- Schemas and stable configuration.
- Small deterministic fixtures required by tests.
- Public signing keys and verification metadata that are intentionally distributable.
- Documentation and runbooks.
- Small generated manifests only when the build or test contract requires them and they are reproducible from source inputs.

## Keep out of Git

- Mutable production market-data snapshots.
- Large generated research panels and provider extracts.
- Production model bundles and retraining outputs.
- Per-symbol or per-week frontend publication payloads that are regenerated by the release pipeline.
- Runtime logs, caches, receipts, temporary validation artifacts, and recovery workspaces.

## Production artifact rule

A production artifact must be addressable by immutable release identity (digest, release ID, or versioned object key) before a mutable pointer is advanced. Build and deploy jobs should materialize the required release explicitly rather than depending on whatever generated files happen to be present in a Git checkout.

## Exceptions

Any generated production artifact committed to Git must have a documented reason, a bounded size, a deterministic generator, and a test that verifies the committed copy is current. Exceptions should be removed once the consuming build can materialize the artifact from its canonical release store.
